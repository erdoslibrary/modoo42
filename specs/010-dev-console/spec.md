**Feature Branch**: `010-dev-console`

**Created**: 2026-10-19

**Status**: Draft

**Input**: User description: "`FR-027`·`FR-028` 개발자 콘솔. 설계의 SSOT는 `docs/trd.md` §2.4, 범위와 인수 테스트는 `docs/requirement.md`의 `FR-027`·`FR-028`과 §3 Test Suite 10, 화면 구성은 `docs/prd.md` F7, 착수 순서와 확정 결정은 `docs/next-steps.md` §4.0이다."

> **범위 확정 (`docs/requirement.md` `FR-027`·`FR-028` · `docs/trd.md` §2.4 · `docs/next-steps.md` §4.0):**
> - **Phase 4의 첫 작업이다.** `FR-018` Grace Period 자동 이관과 `FR-008` 판정창은 달이 바뀌기를 기다리지 않고는 검증할 수 없다. 시각 주입 하네스를 먼저 깔면 뒤 작업이 전부 빨라진다.
> - **`chore` 예외가 아니다.** 라우트 신설(`/api/dev/*`), 도메인 시그니처 변경(`now` 기본값 제거, `createPost`에 `now` 신설), 마이그레이션(`dev_sandbox` 스키마 · publication · 컬럼 권한) 셋 모두에 해당한다.
> - **설계 값과 결정 근거를 이 문서에 복사하지 않는다.** 설계의 SSOT는 `trd.md` §2.4이고, 확정된 결정 7건의 근거는 `next-steps.md` §4.0이다. 두 곳에 두면 갈라진다.
> - **A(`FR-027`)와 B(`FR-028`)를 한 브랜치로 묶는다** (2026-10-19 사용자 결정). 브랜치 안의 순서는 A → B다 — 패널과 시계가 먼저 있어야 샌드박스 진입 흐름을 붙일 수 있다.
> - **2026-10-19 추가 결정 2건이 이 문서에서 처음 확정된다.**
>   1. **게이트를 하나로 합친다.** `MockAuthModal`을 삭제하고 인증 섹션을 콘솔 패널로 흡수한다. 페르소나 전환도 `DEV_CONSOLE_PASSWORD` + 콘솔 세션 뒤에 있다. `NODE_ENV` 게이트를 콘솔 경로에 남기지 않는다 — 게이트가 둘이면 "상용에 열리지 않는다"를 두 곳에서 지켜야 하고, 그것이 이 기능의 유일한 보안 속성이다.
>   2. **샌드박스 범위는 브라우저 단위 앱 전체다.** 유효한 콘솔 세션 쿠키를 들고 있는 동안 그 브라우저의 모든 읽기·쓰기가 `dev_sandbox`를 본다. 콘솔 화면만 격리하면 샌드박스에 쓴 글이 피드·상세에 보이지 않아 `FR-008`·`FR-018`·`FR-020` 검증이 성립하지 않는다.
> - **범위 밖:** 상태 롤백(판정 취소·`COMPLETED` 해제), 동시 샌드박스 2개 이상, 시계 고정(freeze) 모드, 별도 Supabase·Vercel 프로젝트, 전용 테스트 DB(`next-steps.md` U5).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 운영자가 달이 바뀌기를 기다리지 않고 시각 게이트를 통과한다 (Priority: P1)

운영자가 콘솔 패널에 절대 시각(KST)을 입력하고 `[이동]`을 누른다. 그 시각이 서버의 유효 시각이 되어, 판정창(`FR-008`)이 열리고 Grace 기한(`FR-018`)이 지나고 파티가 만료되고(`FR-020`) LIVE 핑이 만료된다(`FR-011`). 화면과 서버가 같은 시각을 본다. `[실제 시각으로 복귀]`로 되돌린다.

**Why this priority**: 이 기능이 존재하는 이유다. 지금은 `FR-008` 판정창·`FR-018` Grace·`FR-020` 파티 만료·`FR-011` LIVE 만료를 검증할 방법이 달을 기다리는 것뿐이다. 나머지 세 스토리는 이 스토리를 안전하게·반복 가능하게 만드는 장치다.

**Independent Test**: 판정창 밖의 정규 스터디를 하나 띄워 두고, 그 글의 `end_date` 월 15일로 이동한 뒤 리더에게 완주 판정 입구가 열리는지 확인한다. 익월 11일로 이동해 Grace 기한 경과 판정이 성립하는지 확인한다. 데이터 격리(US4) 없이도 단독으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 실제 시각이 사이클 중인 정규 스터디, **When** 그 글의 `end_date` 월 15일 이후로 이동한다, **Then** 리더 화면에 완주 판정 입구가 열리고 서버도 같은 판정을 한다. (`req FR-008`, `TC-DEV-01`)
2. **Given** 시계를 이동한 상태, **When** 1초를 기다린다, **Then** 유효 시각이 1초 흐른다. 고정되지 않는다 — LIVE 핑 카운트다운과 만료 전이를 재현하기 위함이다. (`trd.md` §2.4-2)
3. **Given** 유효시간이 남은 LIVE 핑, **When** 만료 직후로 이동한다, **Then** 전광판에서 사라진다. 상태값은 `RECRUITING`으로 남고 조회 Lazy Filter로만 빠진다. (`req FR-011`, `CLAUDE.md` §6.4)
4. **Given** 과거 방향 시각을 입력한다, **When** 제출한다, **Then** 음수 오프셋이 적용되고 범위 제한에 걸리지 않는다. 그 상태에서 만든 글의 생성 시각도 그 과거 시각이다. (`trd.md` §2.4-2, `TC-DEV-12`)
5. **Given** 시계를 이동한 상태, **When** `[실제 시각으로 복귀]`를 누른다, **Then** 오프셋이 사라지고 유효 시각이 실제 시각과 같아진다. (`TC-DEV-02`)
6. **Given** 패널의 시각 입력, **When** 입력을 오프셋으로 환산한 뒤 유효 시각을 복원한다, **Then** 복원값이 입력과 일치한다. 과거 방향도 같다. (`TC-DEV-02`)

### User Story 2 - 운영 도메인에는 콘솔이 존재하지 않는다 (Priority: P1)

운영 도메인의 방문자는 콘솔 입구를 보지 못하고, 콘솔 주소를 직접 입력해도 404를 받는다. 시계 오프셋 쿠키를 손으로 심어도 서버 시각이 변하지 않으므로 판정창·LIVE 1일 1회·파티 만료를 우회할 수 없다.

**Why this priority**: 콘솔은 인증 우회와 시각 우회를 동시에 들고 있다. 상용에서 열리면 `FR-011`(LIVE 1일 1회)과 `FR-008`(판정창)이 무력화되고, 페르소나 전환은 임의 유저로의 로그인이다. US1과 같은 PR에 들어가야 하며 뒤로 미룰 수 없다.

**Independent Test**: `DEV_CONSOLE_PASSWORD`를 비운 환경에서 콘솔 라우트와 `/api/mock-auth`가 404인지, `/login`에 콘솔 입구가 렌더되지 않는지 확인한다. 같은 환경에서 위조한 `modoo42_dev_clock` 쿠키를 붙여 보내고 서버 시각이 변하지 않음을 확인한다.

**Acceptance Scenarios**:

1. **Given** `DEV_CONSOLE_PASSWORD` 미설정 환경, **When** 콘솔 라우트를 호출한다, **Then** 404를 받는다. `/login`의 콘솔 입구도 렌더되지 않는다. (`req FR-028`, `TC-DEV-03`)
2. **Given** `DEV_CONSOLE_PASSWORD` 미설정 환경, **When** `modoo42_dev_clock` 쿠키를 위조해 요청한다, **Then** 서버가 오프셋을 읽지 않고 실제 시각을 반환한다. (`req FR-027`, `TC-DEV-03`)
3. **Given** `DEV_CONSOLE_PASSWORD`가 설정된 환경, **When** 유효한 콘솔 세션 쿠키 없이 `modoo42_dev_clock`만 보낸다, **Then** 오프셋이 적용되지 않는다. 시계는 콘솔 세션에 종속된다. (`TC-DEV-10`)
4. **Given** 콘솔 진입 요청, **When** 비밀번호를 비교한다, **Then** `timingSafeEqual`로 비교하고 성공 시 `modoo42_dev_console` HMAC 서명 쿠키를 발급한다. 평문 플래그 쿠키를 쓰지 않는다. (`req FR-028`)
5. **Given** 시계를 미래로 31일 이상 옮긴 상태, **When** 세션 유효성을 검증한다, **Then** 30일 세션이 유효로 남아 콘솔에서 쫓겨나지 않는다. 세션 만료만 실제 시각을 쓴다. (`req FR-027`, `TC-DEV-04`)

### User Story 3 - 운영자가 현재 세션 해석 소스를 보고 페르소나를 바꾼다 (Priority: P1)

운영자가 패널 인증 섹션에서 현재 세션이 `session`(서명 쿠키) · `persona`(Mock) · `비로그인` 중 무엇으로 해석되는지 본다. 페르소나 버튼으로 유저를 바꾸고, 세션 쿠키 삭제 버튼으로 OAuth 세션을 비운다.

**Why this priority**: 지금 이미 사람을 막고 있는 문제다. `getCurrentUser()`가 `modoo42_session`을 우선하므로(`src/lib/auth.ts:100` 부근), 로컬에서 GitHub OAuth로 한 번 로그인하면 페르소나 버튼이 무반응이 된다. 버그가 아니라 우선순위인데 화면에 아무 단서가 없다. 리더·멤버·비참여자 시점 전환은 `FR-008`·`FR-017` 검증의 전제이기도 하다.

**Independent Test**: OAuth로 로그인한 로컬 상태에서 패널을 열어 해석 소스가 `session`으로 표시되는지, 세션 쿠키 삭제 후 페르소나 버튼이 다시 먹는지 확인한다.

**Acceptance Scenarios**:

1. **Given** `modoo42_session`이 있는 상태, **When** 패널을 연다, **Then** 해석 소스가 `session`으로 표시된다. 페르소나 버튼을 눌러도 유저가 바뀌지 않는 이유가 화면에서 읽힌다. (`prd.md` F7)
2. **Given** 같은 상태, **When** 세션 쿠키 삭제 버튼을 누른다, **Then** 해석 소스가 `비로그인`으로 바뀌고 이후 페르소나 선택이 반영된다. (`prd.md` F7)
3. **Given** 페르소나 4종(`gs_leader`·`gs_member`·`seoul_member`·`github_only`), **When** 하나를 고른다, **Then** 해당 유저로 해석되고 해석 소스가 `persona`로 표시된다. 페르소나 정의는 `src/lib/personas.ts` 한 곳에서 읽는다. (`req FR-016`)
4. **Given** 기존 `MockAuthModal`, **When** 콘솔 패널을 올린다, **Then** `MockAuthModal`을 삭제하고 `src/app/layout.tsx`의 마운트를 콘솔 패널로 교체한다. 플로팅 패널이 2개 뜨지 않는다. (2026-10-19 사용자 결정)
5. **Given** 페르소나 전환 엔드포인트, **When** 게이트를 정한다, **Then** 콘솔과 같은 기준(`DEV_CONSOLE_PASSWORD` + 유효한 콘솔 세션)을 쓴다. `NODE_ENV` 전용 게이트를 남기지 않는다. (2026-10-19 사용자 결정)

### User Story 4 - 콘솔 세션의 쓰기가 운영 테이블에 닿지 않는다 (Priority: P2)

콘솔 세션을 열면 그 브라우저가 보는 데이터가 `dev_sandbox` 스키마로 바뀐다. 진입 시 샌드박스를 비우고 운영 데이터를 복사해 오되, 오픈채팅방 초대 링크는 비운다. 콘솔에서 글을 만들고 참여하고 판정해도 운영 피드에는 아무 변화가 없다. 쿠키를 지우면 운영 데이터로 돌아온다.

**Why this priority**: `DATABASE_URL`이 하나이고 배포본과 공유되므로(`next-steps.md` §4.0), 격리가 없으면 US1의 시각 이동 실험이 그대로 운영 피드에 쌓인다. US1만으로도 검증은 되지만, 격리 없이 반복하면 피드가 쓰레기로 찬다.

**Independent Test**: 콘솔 세션에서 스터디를 만들고 참여·판정까지 수행한 뒤, 콘솔 쿠키를 지우고 같은 화면을 열어 운영 피드의 행 수가 그대로인지 확인한다. 스냅샷 직후 샌드박스의 `chat_url`이 전건 비어 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 유효한 콘솔 세션, **When** 글 생성·참여·판정을 수행한다, **Then** `public` 테이블의 행 수가 변하지 않는다. (`req FR-028`, `TC-DEV-09`)
2. **Given** 콘솔 진입, **When** 샌드박스를 초기화한다, **Then** `participants` → `posts` → `users` 순으로 비운다. `posts.leader_id`가 `onDelete: 'restrict'`이기 때문이다. (`trd.md` §2.4-5)
3. **Given** 스냅샷 직후, **When** 샌드박스의 글을 조회한다, **Then** 실제 초대 링크가 한 건도 남아 있지 않고 전부 `dev-sandbox` 더미 링크이며, 플랫폼 배지와 `reference_url`은 그대로 보인다. (`req FR-028`, `TC-DEV-05`)
4. **Given** 초기화 대상 스키마, **When** 파괴적 문장을 실행한다, **Then** 문장이 항상 스키마를 수식하고, 실행 전에 대상 스키마 이름을 상수와 대조해 단정한다. 대상이 `public`이면 실행 전에 거부한다. (`req FR-028`, `TC-DEV-06`)
5. **Given** 콘솔 세션 쿠키가 있는 브라우저, **When** 대시보드·상세·프로필·판정 흐름을 돈다, **Then** 모든 읽기와 쓰기가 샌드박스를 본다. 현재 유저 해석(`src/lib/auth.ts`)도 샌드박스에서 읽는다. 쿠키가 없는 동시 요청은 운영 데이터를 본다. (2026-10-19 사용자 결정, `TC-DEV-11`)
6. **Given** 콘솔 세션, **When** 실시간 갱신을 구독한다, **Then** 샌드박스 쪽 변경이 1초 안에 반영되고 구독 페이로드에 `chat_url`이 없다. (`req NFR-004`, `trd.md` §2.4-7, §5)
7. **Given** 콘솔 쿠키를 지운다, **When** 같은 화면을 다시 연다, **Then** 운영 데이터가 보인다. 복귀에 별도 조작이 필요 없다.

### User Story 5 - 운영자가 경계 시각에 한 번에 도달한다 (Priority: P2)

운영자가 시나리오 버튼 하나로 그 상태를 만드는 시각으로 이동한다. 글마다 경계가 다른 파티 `end_date`와 LIVE `expires_at`은 상세 모달의 "이 글 기준으로 이동" 입구로 맞춘다.

**Why this priority**: US1으로 이미 검증은 가능하지만, 매번 KST 경계를 손으로 계산해 입력해야 한다. 프리셋은 반복 비용을 줄이는 장치이므로 시계 다음이다.

**Independent Test**: 프리셋 8종을 눌러 각각 기대한 경계 밖/안에 도달하는지 확인한다. 파티 글의 "이 글 기준으로 이동"으로 그 글만 만료되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 시나리오 프리셋, **When** 목록을 센다, **Then** 8종이다 — 모집창 시작 · 모집창 밖 · 판정창 열림 · Grace 만료 · 파티 종료 직후 · LIVE 만료 직전 · LIVE 만료 직후 · 다음 KST 자정. (`req FR-027`, `prd.md` F7)
2. **Given** 각 프리셋, **When** 시각을 산출한다, **Then** KST 경계 기준의 기대 시각을 반환한다. 모집창 시작은 당월 15일 00:00 KST 이후, Grace 만료는 `end_date` 월 기준 익월 11일 00:00 KST 이후다. (`TC-DEV-01`)
3. **Given** "다음 KST 자정" 프리셋, **When** 이동한다, **Then** LIVE 핑 1일 1회 제한이 리셋되어 같은 유저가 다시 등록할 수 있다. (`req FR-011`)
4. **Given** 파티 또는 LIVE 핑 상세 모달, **When** "이 글 기준으로 이동"을 누른다, **Then** 그 글의 `end_date`·`expires_at` 경계로 이동한다. 프리셋만으로는 글마다 다른 경계를 맞출 수 없다. (`prd.md` F7)
5. **Given** 패널 시계 섹션, **When** 화면을 본다, **Then** 현재 유효 시각(KST)이 1초마다 갱신되고, 절대 시각 입력과 `[이동]`·`[실제 시각으로 복귀]`가 있다. 오프셋 숫자는 노출하지 않는다. (`prd.md` F7)

### User Story 6 - 2창 실시간 검증이 서로를 지우지 않는다 (Priority: P3)

운영자가 두 창(일반 창 + 시크릿 창)으로 콘솔에 들어가 실시간 동기화를 검증한다. 두 번째 창의 진입이 첫 창의 작업을 지우지 않고 같은 샌드박스에 합류한다.

**Why this priority**: `NFR-004`의 2창 검증 절차(`specs/006-dashboard-realtime/quickstart.md` §4)가 이미 있다. 표식이 없으면 두 번째 진입이 초기화를 돌려 첫 창의 데이터를 날리고, 그 검증 절차가 콘솔 안에서 성립하지 않는다. 다만 US1~US5가 없으면 검증할 대상 자체가 없으므로 뒤에 둔다.

**Independent Test**: 한 창에서 콘솔에 들어가 글을 만들고, 두 번째 창으로 진입한 뒤 첫 창의 글이 남아 있는지 확인한다. 표식 TTL이 지난 뒤의 진입이 초기화를 수행하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 유효한 세션 표식, **When** 두 번째 창이 진입한다, **Then** 초기화를 건너뛰고 기존 샌드박스에 합류한다. (`req FR-028`, `TC-DEV-07`)
2. **Given** TTL이 지난 표식, **When** 진입한다, **Then** 초기화와 스냅샷을 수행한다. (`TC-DEV-07`)
3. **Given** 두 창이 같은 샌드박스에 있다, **When** 한 창에서 참여한다, **Then** 다른 창의 인원 수가 1초 안에 갱신된다. (`req NFR-004`)
4. **Given** 운영자 2명 이상, **When** 지원 범위를 정한다, **Then** 지원하지 않는다. 스키마가 하나이므로 동시 샌드박스는 1개다. (`req FR-028`)

### Edge Cases

- **시계를 미래로 31일 이상 옮기면 어떻게 되는가?** 30일 세션이 만료 판정되어 콘솔에서 쫓겨날 수 있다. 세션 검증만 실제 시각을 쓴다. (`TC-DEV-04`)
- **판정 후 과거로 돌아가면 어떻게 되는가?** DB는 되돌아가지 않으므로 "사이클 중인데 이미 `COMPLETED`"인 글이 보인다. 데이터 손상이 아니며 상태 롤백은 만들지 않는다. 패널 하단에 "시계는 되돌아가지만 데이터는 되돌아가지 않습니다" 한 줄을 둔다. (`trd.md` §2.4-8, `prd.md` F7)
- **탭을 오래 열어 두면 어떻게 되는가?** 시계가 흐르므로 KST 날짜 경계를 저절로 넘는다. 프리셋 재클릭으로 되돌린다. 고정 모드는 없다. (`trd.md` §2.4-2)
- **오프셋 쿠키 값이 정수가 아니거나 손상되면 어떻게 되는가?** 오프셋을 0으로 보고 실제 시각을 쓴다. 요청을 실패시키지 않는다.
- **비우지 않고 스냅샷을 다시 복사하면 어떻게 되는가?** `users.github_id`·`users.login` 유일 제약에 걸린다. "비우기 + 복사"는 한 묶음이다. (`trd.md` §2.4-5)
- **`dev_sandbox` 재생을 빠뜨리면 어떻게 되는가?** `drizzle-kit`은 `public`만 관리하므로 스키마 변경 뒤 샌드박스가 뒤처진다. 진입이 실패해야 하고, 조용히 낡은 스키마로 동작하지 않아야 한다.
- **샌드박스 쪽 컬럼 권한 복제를 빠뜨리면 어떻게 되는가?** 실시간 구독자에게 `chat_url`이 샌다. publication 등록과 컬럼 단위 권한은 둘 다 필요하다. (`trd.md` §2.4-7, §5)
- **과거로 이동한 상태에서 글을 만들면 생성 시각은 무엇인가?** 유효 시각으로 기록된다 (FR-022). 그래서 과거 사이클 스터디를 만들어 아카이브·명예의 전당을 검증할 수 있다. 반대로 과거 이동 중 만든 단기 파티는 `end_date`가 이미 지나 즉시 만료로 보일 수 있다 — 의도된 결과다.
- **콘솔 세션 쿠키만 있고 샌드박스가 비어 있으면 어떻게 되는가?** 표식이 없으므로 다음 진입이 초기화와 스냅샷을 수행한다. 빈 화면을 그대로 두지 않는다.
- **`pnpm test`는 어느 스키마를 보는가?** `public`이다. 샌드박스는 요청 스코프의 콘솔 세션에 종속되므로 테스트 격리를 대체하지 않는다. (`next-steps.md` U5)

- **FR-020** (A, US5): 패널은 인증 · 시계 · 시나리오 3섹션이어야 한다. 시계 섹션은 현재 유효 시각(KST)을 1초마다 표시하고 절대 시각 입력 + `[이동]`·`[실제 시각으로 복귀]`를 둔다. 입력은 절대 시각이고 **오프셋 숫자는 노출하지 않는다.** 시나리오 섹션은 프리셋 8종이다. 패널 하단에 되돌리기의 한계 한 줄을 둔다. (`req FR-027`, `prd.md` F7)
- **FR-021** (A, US5): 상세 모달에 개발 전용 "이 글 기준으로 이동" 입구를 둬야 한다. 파티 `end_date`와 LIVE `expires_at`은 글마다 다르므로 프리셋만으로는 경계를 맞출 수 없다. (`prd.md` F7)
- **FR-022** (A, US1): 도메인 삽입 경로가 `created_at`·`joined_at`을 **유효 시각으로 명시 삽입해야 한다** (2026-10-19 승인). 현재 `src/db/schema.ts:27`·`60`·`72`가 `defaultNow()`라 과거를 **볼 수는 있어도 과거에 쓸 수는 없고**, 그러면 과거 사이클 스터디를 만들 수 없어 아카이브·명예의 전당 검증이 막힌다. 컬럼 기본값은 그대로 두므로 **마이그레이션이 없다.** 지점은 `created_at` 2곳(`posts.ts:70`·`145`), `joined_at` 삽입 2곳(`92`·`242`)과 재참여 갱신 1곳(`239`), 도메인 `updated_at` 4곳(`187`·`444`·`478`·`507`)이다 (`research.md` R6). 판정이 유효 시각에 일어났으면 그 기록도 같은 시각이어야 하므로 도메인 `updated_at`을 함께 옮긴다.
- **FR-023** (A, US2): 세션·인증 레코드의 시각은 실제 시각을 유지해야 한다 — `src/lib/auth.ts:70`·`77`의 로그인 시 `updated_at`이다. FR-006과 같은 이유로 dev 시계를 따르지 않는다.
- **FR-024** (전 범위): `public` 스키마와 API 응답 계약을 바꾸지 않아야 한다. 마이그레이션은 샌드박스 스키마 재생·publication 등록·컬럼 권한 복제로 한정한다. 스키마를 바꾸면 `src/db/schema.ts`와 `docs/trd.md` §3.2를 같은 PR에서 함께 고친다. (`CLAUDE.md` §3)
- **FR-025** (범위 밖 고정): 상태 롤백(판정 취소·`COMPLETED` 해제), 시계 고정(freeze) 모드, 동시 샌드박스 2개 이상, 별도 Supabase·Vercel 프로젝트를 **만들지 않아야 한다.** 다음 대조에서 "누락"으로 세지 않는다. (`req FR-027`·`FR-028`, `next-steps.md` §4.0)
- **FR-026** (전 범위): 이 작업이 전용 테스트 데이터베이스(`next-steps.md` U5)를 대체하지 않아야 한다. `pnpm test`는 여전히 공용 인스턴스의 `public`에 붙으므로 `NFR-006`의 CI 편입 선행 조건은 그대로 남는다.

### Key Entities

- **시계 오프셋 (`DevClockOffset`)**: `modoo42_dev_clock` 쿠키가 담는 정수 1개(`offsetMs`). 유효 시각은 `실제 시각 + offsetMs`이고, 패널 입력은 절대 시각(KST)이라 제출 시 `입력 − 실제 now`로 환산한다. 음수(과거)를 허용하고 범위 제한이 없다. 손상값은 0으로 본다.
- **콘솔 세션 (`DevConsoleSession`)**: `modoo42_dev_console` HMAC 서명 쿠키. 콘솔 라우트 접근·오프셋 반영·샌드박스 핸들 선택 세 가지의 공통 조건이다. 쿠키 삭제가 운영 복귀다.
- **샌드박스 스키마 (`dev_sandbox`)**: 같은 데이터베이스 안의 두 번째 스키마. 세션 중에는 물리적으로 저장되며, "저장되지 않는다"는 **세션 사이**에 대해서만 성립한다. 참여 트랜잭션이 행 잠금을 쓰고 RSC와 Route Handler가 별개 요청이므로 메모리 보관으로는 `NFR-001`이 성립하지 않는다.
- **세션 표식 (`SandboxSessionMarker`)**: 샌드박스 안의 시작 시각 + TTL 행. 유효하면 재진입이 초기화를 건너뛰고 합류한다. 2창 실시간 검증을 살리는 장치다.
- **시나리오 프리셋 (`ScenarioPreset`)**: 8종. 모집창 시작 · 모집창 밖 · 판정창 열림 · Grace 만료 · 파티 종료 직후 · LIVE 만료 직전 · LIVE 만료 직후 · 다음 KST 자정. 각 프리셋은 KST 경계 기준으로 그 상태를 만드는 절대 시각을 산출한다.
- **시각 소스 2종 (`ClockSource`)**: `serverNow()`(도메인 판단과 도메인 레코드 타임스탬프) / `realNow()`(세션 만료 검증과 인증 레코드). 후자를 쓰는 자리는 `src/lib/session.ts`와 `src/lib/auth.ts`의 로그인 갱신뿐이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 운영자가 판정창·Grace 만료·파티 만료·LIVE 만료·LIVE 자정 리셋 5종을 **달을 기다리지 않고** 전부 재현한다. 각 재현은 패널 조작 2회(프리셋 클릭 또는 시각 입력 + 화면 확인) 안에 끝난다.
- **SC-002**: 도메인 함수에 `now` 기본값이 0건이고, RSC·Route Handler에 직접 `new Date()` 호출이 0건이다. 예외는 `src/lib/session.ts`와 `src/lib/auth.ts`의 로그인 갱신뿐이다.
- **SC-003**: `DEV_CONSOLE_PASSWORD` 미설정 환경에서 콘솔 라우트·페르소나 엔드포인트가 전부 404이고, 콘솔 입구와 패널이 렌더되지 않는다.
- **SC-004**: 위조한 시계 오프셋 쿠키를 붙여도, 콘솔 게이트가 닫힌 환경에서 서버 유효 시각이 실제 시각과 1초 이내로 같다.
- **SC-005**: 시계를 미래로 31일 이상 옮긴 상태에서 콘솔 세션과 로그인 세션이 모두 유효하게 남는다.
- **SC-006**: 콘솔 세션에서 수행한 글 생성·참여·판정 후 `public` 테이블 3종의 행 수 변화가 0이다.
- **SC-007**: 스냅샷 직후 샌드박스 글의 `chat_url`에 운영 값이 0건이고(전부 `dev-sandbox` 더미 또는 `null`), 실시간 구독 페이로드에는 `chat_url`이 아예 없다.
- **SC-008**: 초기화 대상 스키마가 `dev_sandbox`가 아닐 때 파괴적 문장이 **실행되기 전에** 거부된다.
- **SC-009**: 두 창이 같은 샌드박스에 합류하고, 한 창의 참여가 다른 창에 1초 이내 반영된다. 두 번째 진입이 첫 창의 데이터를 지우지 않는다.
- **SC-010**: 플로팅 패널이 화면에 1개이고 `MockAuthModal`이 저장소에 0건이다. 페르소나 전환은 콘솔 패널 안에서만 가능하다.
- **SC-011**: 로컬 필수 게이트 5종(`pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm drizzle-kit check`)이 100% 통과한다. `public` 스키마 대상 마이그레이션이 0건이다.

## Assumptions

- **콘솔 게이트가 하나다.** 로컬 개발자도 `.env.local`에 `DEV_CONSOLE_PASSWORD`를 넣고 한 번 로그인해야 페르소나를 쓸 수 있다. 콘솔 세션 쿠키가 유지되므로 매 요청마다 입력하지는 않는다. 이 마찰을 받아들이는 대신 상용 차단 검증 경로를 하나로 줄인다 (2026-10-19 사용자 결정).
- **샌드박스는 브라우저 단위다.** 콘솔 세션 쿠키를 들고 있는 동안 그 브라우저의 모든 화면이 샌드박스를 본다. 쿠키가 없는 브라우저는 영향을 받지 않으므로, 같은 배포본을 다른 사람이 동시에 정상 사용할 수 있다 (2026-10-19 사용자 결정).
- **스냅샷이 행 식별자를 보존한다.** 그래서 `public`에서 발급된 로그인 세션이 샌드박스 안에서도 같은 유저로 해석된다. 보존하지 않으면 콘솔 진입 직후 로그인이 풀린다.
- **레코드 타임스탬프는 유효 시각을 따른다** (FR-022, 2026-10-19 승인). 과거 사이클 아카이브를 만들 수 있는 유일한 경로이고, 컬럼 기본값을 건드리지 않으므로 마이그레이션이 없다. 대가는 피드 정렬(`created_at`)이 dev 시계에 따라 흔들리는 것이다. 예외는 세션·인증 레코드뿐이다 (FR-023).
- **`DATABASE_URL`은 하나이고 배포본과 공유한다.** 샌드박스는 이 공유를 콘솔 세션 범위에서만 해소하며, `pnpm test`의 격리(U5)는 별건으로 남는다.
- **`drizzle-kit`은 `public`만 관리한다.** 샌드박스 스키마는 기존 마이그레이션 SQL을 샌드박스 대상으로 재생해 만들고, `public` 스키마가 바뀔 때마다 재생이 필요하다. 열거형도 스키마 스코프라 함께 생성된다.
- **디자인 원본이 없다.** 패널은 기존 `MockAuthModal`의 네오브루탈리즘 스타일을 이어 쓰고, 토큰과 글리프 예외는 `CLAUDE.md` §10과 `.claude/rules/anti-ai-slop.md`를 따른다.
- **`FR-018` Grace Period Cron 자체는 이 작업 범위가 아니다.** 이 작업은 그 검증 수단을 만든다. Cron 구현은 같은 Phase 4의 뒤 항목이다.
