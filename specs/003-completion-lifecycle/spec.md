## User Scenarios & Testing *(mandatory)*

### User Story 1 - 완주 벌크 판정 (Priority: P1)

정규 스터디 리더가 사이클 종료 무렵 상세 화면에서 `[스터디 종료 및 결과 기록]`을 열고, 참여자 체크박스(기본 전원 체크)에서 중도 이탈자만 해제해 완주/미완주를 한 번에 판정한다. 결과물 링크(증빙 URL)는 원하면 덧붙인다. 확정하면 글은 `COMPLETED`가 되고, 리더는 리더 횟수 1회, 완주 판정된 멤버는 완주 횟수 1회가 쌓인다.

**Why this priority**: 플랫폼의 "완주 기록" 가치의 핵심이며, 명예의 전당과 랭킹(US4)이 이 결과를 원천 데이터로 쓴다. 이것 없이는 Phase 2 A의 나머지가 의미가 없다.

**Independent Test**: 판정 창 안의 `CLOSED` 정규 스터디에 리더가 멤버 2명 중 1명만 완주로 판정 → 글 `COMPLETED`, 완주 멤버 `completed_count + 1`, 미완주 멤버 카운트 불변, 리더 `leader_count + 1`이 한 번에 반영되는지 확인.

**Acceptance Scenarios**:

1. **Given** 판정 창 안의 `RECRUITING`/`CLOSED` 정규 스터디, **When** 리더가 전 참여자를 판정(증빙 URL 유무 무관)해 제출, **Then** 글 `status = 'COMPLETED'`, 완주 멤버 `completed_count + 1`, 리더 `leader_count + 1`이 동시에 반영되고 참여자별 판정 결과(`COMPLETED`/`INCOMPLETE`)가 기록된다. (TC-COMPLETE-01)
2. **Given** 증빙 URL 없이 판정 제출, **When** 처리, **Then** 정상 완주 처리된다. 증빙 URL을 넣었다면 `https://`가 아닐 때 400.
3. **Given** `COMPLETED` 글, **When** 참여·취소·정보 수정·재판정 시도, **Then** 400 차단. (TC-COMPLETE-02)
4. **Given** 글, **When** 비리더가 판정 호출, **Then** 403 Forbidden. (TC-LEADER-01)
5. **Given** 판정 창 밖(예: 사이클 종료월 14일 이전), **When** 리더가 판정 시도, **Then** 400 차단.
6. **Given** 판정 목록이 실제 참여자와 불일치(누락·중복·비참여자 포함), **When** 제출, **Then** 400 차단, 아무 카운트도 바뀌지 않는다.
7. **Given** 같은 글에 판정 요청이 동시에 2번 들어옴, **When** 처리, **Then** 정확히 1건만 성공하고 카운트는 한 번만 가산된다.
8. **Given** `CANCELLED` 글, **When** 판정 시도, **Then** 400 차단.
9. **Given** 단기 파티(`PARTY`) 글, **When** 리더가 판정 시도, **Then** 400 차단. 단기 파티는 판정 없이 `CLOSED`로 단순 종료한다.

### User Story 2 - Post-mortem 실패 회고 등록 (Priority: P2)

목표를 달성하지 못한 정규 스터디의 리더가 실패 원인과 교훈을 텍스트로 남긴다. 글 상태는 그대로(`CLOSED`/`RECRUITING`) 두고 회고만 기록되며, 누구의 카운트도 오르지 않는다. 회고는 🪦Post-mortem 목록에 남아 다음 동료의 참고 자산이 된다.

**Why this priority**: 실패도 자산으로 남긴다는 제품 철학의 반쪽. 완주 판정(US1)과 같은 종료 모달의 대안 경로라 P2.

**Independent Test**: 판정 창 이후 `CLOSED` 정규 스터디에 리더가 회고 등록 → `postmortem_text` 저장, 상태 `CLOSED` 유지, 리더·멤버 카운트 불변 확인.

**Acceptance Scenarios**:

1. **Given** 판정 창이 열린 이후의 `RECRUITING`/`CLOSED` 정규 스터디, **When** 리더가 회고(1~1000자) 등록, **Then** 회고 저장, 상태 불변, 카운트 미가산. (FR-009)
2. **Given** 이미 회고가 있는 글, **When** 리더가 다시 등록, **Then** 새 내용으로 덮어쓴다(뒤늦은 보강 허용).
3. **Given** 회고가 등록된 글, **When** 리더가 완주 판정 시도, **Then** 400 차단 (실패로 확정된 사이클).
4. **Given** `COMPLETED`/`CANCELLED` 글, **When** 회고 등록 시도, **Then** 400 차단.
5. **Given** 단기 파티(`PARTY`) 글, **When** 회고 등록 시도, **Then** 400 차단 (정규 스터디 전용).
6. **Given** 글, **When** 비리더가 회고 등록 시도, **Then** 403 Forbidden.

### User Story 3 - 템플릿 프리셋 특화 데이터 (Priority: P2)

리더가 정규 스터디를 개설할 때 6종 프리셋(코딩테스트·모각코·책 완독·듀오링고·음악 감상·자유) 중 하나를 고르면, 해당 템플릿 전용 항목(예: 책 제목, 학습 언어)을 함께 입력한다. 서버는 템플릿별 규칙으로 이 항목을 검증하고 저장한다. 새 템플릿은 DB 변경 없이 코드 정의 1건으로 추가된다.

**Why this priority**: 개설 품질과 확장성을 높이지만, 완주 루프(US1)는 템플릿 없이도 성립하므로 P2.

**Independent Test**: `book` 템플릿으로 책 제목을 넣어 개설 → 저장 확인. 책 제목 누락 시 400. 등록되지 않은 템플릿 ID → 400.

**Acceptance Scenarios**:

1. **Given** 등록된 템플릿 ID와 그 규칙에 맞는 특화 데이터, **When** 정규 스터디 개설, **Then** 특화 데이터가 그대로 저장되고 상세 조회에 노출된다.
2. **Given** 템플릿 규칙 위반(필수 항목 누락·형식 오류·미정의 항목), **When** 개설, **Then** 400.
3. **Given** 등록되지 않은 템플릿 ID, **When** 개설, **Then** 400.
4. **Given** 템플릿 없이 특화 데이터만 보냄, **When** 개설, **Then** 400.
5. **Given** 템플릿 ID 없이 개설, **When** 처리, **Then** Phase 1과 동일하게 정상 개설(템플릿은 선택).
6. **Given** 단기 파티(`PARTY`)에 템플릿 지정, **When** 개설, **Then** 400 (템플릿은 정규 스터디 전용).
7. **Given** 템플릿 목록 조회, **When** 요청, **Then** 6종 프리셋의 ID·이름·기본 설명·기본 태그가 반환된다.

### User Story 4 - 명예의 전당 & 성실 멤버 랭킹 (Priority: P2)

모든 멤버가 🏆명예의 전당에서 완주한 정규 스터디 카드와 결과물 링크를 보고, 🪦Post-mortem 목록에서 실패 회고를 읽는다. 성실 멤버 랭킹 위젯은 상위 5명을 골드/실버/브론즈로 보여준다.

**Why this priority**: 완주 기록을 사회적 보상으로 바꾸는 노출 계층. 데이터는 US1·US2가 만들고, 이 스토리는 읽기만 하므로 P2.

**Independent Test**: 완주 글 1건·회고 글 1건·취소 글 1건이 있을 때 명예의 전당에는 완주 글만, Post-mortem 목록에는 회고 글만 나오는지 확인. 카운트가 다른 유저 6명이 있을 때 랭킹이 규칙대로 5명만 반환하는지 확인.

**Acceptance Scenarios**:

1. **Given** `COMPLETED` 정규 스터디, **When** 명예의 전당 조회, **Then** 제목·리더·완주 멤버 목록·증빙 URL(있을 때)·사이클이 노출된다. `chat_url`은 포함하지 않는다.
2. **Given** `CANCELLED` 글·미판정 글·단기 파티, **When** 명예의 전당 조회, **Then** 노출되지 않는다.
3. **Given** 회고가 등록된 정규 스터디, **When** Post-mortem 목록 조회, **Then** 제목·리더·회고 본문·사이클이 노출된다.
4. **Given** 유저별 완주/리더 기록, **When** 랭킹 조회, **Then** 완주 횟수 내림차순 → 리더 횟수 내림차순 → `intra_id` 오름차순으로 상위 5명이 순위·`intra_id`·캠퍼스·완주 횟수·리더 횟수와 함께 반환된다.
5. **Given** 기록이 하나도 없는 유저, **When** 랭킹 조회, **Then** 랭킹에 포함되지 않는다.

---

### Edge Cases

- 리더 혼자만 남은(다른 참여자 0명) 스터디는 완주 판정할 수 없다. 완주 멤버가 1명 이상이어야 완주로 인정한다 — 리더 횟수를 혼자 쌓는 것을 막기 위함. 이 경우 리더는 Post-mortem 경로를 쓴다.
- 판정 목록에 리더 본인을 넣으면 400. 리더는 판정 대상이 아니며 자동으로 완주 처리된다.
- 판정 도중 트랜잭션이 실패하면 참여자 상태·카운트·글 상태 중 어느 것도 일부만 바뀌지 않는다.
- 판정과 동시에 신규 참여가 들어오면, 둘 중 하나가 먼저 확정되고 나머지는 바뀐 상태 기준으로 처리된다(판정 후 참여는 `COMPLETED`라 400, 참여 후 판정은 참여자 불일치로 400).
- 존재하지 않는 글 ID로 판정·회고 요청 → 404.
- 회고 본문이 공백만 있으면 400.
- 템플릿 정의가 나중에 바뀌어도 이미 저장된 특화 데이터는 재검증하지 않는다(저장 시점 규칙 기준).

## Requirements *(mandatory)*

### Functional Requirements

**템플릿 (FR-007)**

- **FR-001**: 시스템은 6종 기본 프리셋(코딩테스트·모각코·책 완독·듀오링고·음악 감상·자유)을 템플릿 등록부에 제공한다. 각 템플릿은 ID·이름·기본 설명·기본 태그·기본 증빙 유형·(선택) 특화 데이터 규칙을 가진다.
- **FR-002**: 정규 스터디 개설 시 템플릿 ID와 특화 데이터를 선택 입력할 수 있다. 템플릿 ID가 있으면 서버가 해당 템플릿 규칙으로 특화 데이터를 검증하고, 위반 시 400. 미등록 템플릿 ID·템플릿 없는 특화 데이터·단기 파티의 템플릿 지정은 400.
- **FR-003**: 템플릿을 고른 글은 템플릿의 기본 증빙 유형을 글의 증빙 유형으로 기록한다.
- **FR-004**: 신규 템플릿은 DB 스키마 변경 없이 등록부에 정의 1건을 추가하는 것만으로 개설·검증에 반영된다.
- **FR-005**: 인증된 유저는 템플릿 목록(ID·이름·기본 설명·기본 태그)을 조회할 수 있다.

**완주 판정 (FR-008)**

- **FR-006**: 리더만 자기 글을 판정할 수 있다. 비리더는 403.
- **FR-007**: 정규 스터디 판정 창은 사이클 종료월(`end_date`가 속한 달) 15일 00:00 KST부터 익월 10일 23:59:59 KST까지다. 창 밖 판정은 400.
- **FR-008**: 판정 대상 글은 `RECRUITING` 또는 `CLOSED`이고 회고가 없어야 한다. `COMPLETED`·`CANCELLED`·회고 등록 글은 400.
- **FR-009**: 판정 목록은 리더를 제외한 현재 `JOINED` 참여자 전원을 정확히 1번씩 포함해야 하며, 각 항목은 완주/미완주 중 하나다. 누락·중복·비참여자·리더 포함은 400. 완주 멤버가 1명 이상이어야 한다.
- **FR-010**: 증빙 URL은 선택이며, 입력 시 `https://`만 허용한다.
- **FR-011**: 판정 확정 시 참여자별 상태 기록(`COMPLETED`/`INCOMPLETE`, 리더는 `COMPLETED`), 완주 멤버 `completed_count + 1`, 리더 `leader_count + 1`, 글 `status = 'COMPLETED'` 및 증빙 URL 저장을 단일 트랜잭션에서 원자적으로 처리한다. 동시 판정 요청에도 가산은 정확히 1회다.
- **FR-012**: 완주 판정은 정규 스터디(`STUDY`) 전용이다. 단기 파티(`PARTY`) 판정 시도는 400이며, 단기 파티는 카운트 가산을 받지 않는다. (2026-10-18 결정: 단기 파티는 판정 없이 `CLOSED`로 단순 종료. requirement.md FR-008의 단기 파티 문구를 이에 맞게 정정)

**Post-mortem (FR-009)**

- **FR-013**: 리더는 판정 창이 열린 이후(사이클 종료월 15일 00:00 KST부터, 종료 기한 없음) `RECRUITING`/`CLOSED` 정규 스터디에 회고(공백 제외 1~1000자)를 등록·덮어쓸 수 있다. 비리더 403, 단기 파티·`COMPLETED`·`CANCELLED`·창 이전은 400.
- **FR-014**: 회고 등록은 상태 전이가 아니다. 글 상태는 유지되고 리더·멤버 카운트는 가산되지 않는다.

**명예의 전당 & 랭킹 (FR-010)**

- **FR-015**: 인증된 유저는 명예의 전당(`COMPLETED` 정규 스터디 목록: 제목·리더·완주 멤버·증빙 URL·사이클·템플릿)과 Post-mortem 목록(회고 등록 정규 스터디: 제목·리더·회고 본문·사이클)을 최신 완료순으로 조회할 수 있다. 두 목록 모두 `chat_url`을 포함하지 않는다.
- **FR-016**: 인증된 유저는 성실 멤버 랭킹 상위 5명을 조회할 수 있다. 각 항목은 순위·`intra_id`·캠퍼스·완주 횟수·리더 횟수를 가진다. 완주·리더 기록이 모두 0인 유저는 제외한다. 정렬 규칙: 완주 횟수 내림차순 → 리더 횟수 내림차순 → `intra_id` 오름차순. (2026-10-18 결정: 완주율 대신 완주 횟수 우선. requirement.md FR-010·trd.md §4 문구를 이에 맞게 정정)
- **FR-017**: 랭킹·목록은 캠퍼스로 분리하거나 필터링하지 않는다. 프로필 이미지 대신 `intra_id` 이니셜을 쓴다.

**범위 밖(이 Phase 비대상):** LIVE 핑(FR-011 req)·CLI `/api/list`(FR-012 req)는 Phase 2 B. 익월 10일 도과 미판정 스터디 자동 Post-mortem 이관(FR-018 req, Cron)은 Phase 4. 대시보드 UI 렌더링·Realtime은 Phase 3. 템플릿 전용 폼 컴포넌트(`CustomFormField`)는 Phase 3 UI 포팅에서 다룬다. 단기 파티의 `end_date` 도래 시 `CLOSED` 종료 처리는 이 spec이 다루지 않는다(요구사항 FR에 미배정).

### Key Entities

- **Template (템플릿)**: 코드에 정의된 스터디 유형 플러그인. ID·이름·기본 설명·기본 태그·기본 증빙 유형·특화 데이터 규칙. DB 테이블이 아니다.
- **Post (게시글)**: Phase 1 속성에 더해 템플릿 ID, 템플릿 특화 데이터, 증빙 유형, 증빙 URL, 회고 본문을 가진다. 완주 판정 시 `COMPLETED`(최종 상태).
- **Participant (참여자)**: 판정 결과로 상태가 `JOINED`에서 `COMPLETED` 또는 `INCOMPLETE`로 바뀐다.
- **User (유저)**: 누적 완주 횟수(`completed_count`)와 누적 리더 횟수(`leader_count`)를 가진다. 랭킹의 원천.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 완주 판정 1건당 리더 횟수와 각 완주 멤버의 완주 횟수가 정확히 1씩 오른다. 같은 글에 판정 요청 5건을 동시에 보내도 가산은 1회뿐이다.
- **SC-002**: 판정 도중 실패한 요청은 카운트·참여자 상태·글 상태 중 어느 것도 바꾸지 않는다 (부분 반영 0건).
- **SC-003**: 증빙 URL 없이 제출한 판정이 100% 정상 완주 처리된다.
- **SC-004**: `COMPLETED`·`CANCELLED` 글에 대한 참여·수정·취소·재판정·회고 시도가 100% 400으로 차단된다. (NFR-003, TC-COMPLETE-02)
- **SC-005**: 비리더의 판정·회고 시도가 100% 403으로 차단된다. (TC-LEADER-01)
- **SC-006**: 회고 등록 전후로 리더·멤버 카운트와 글 상태가 변하지 않는다.
- **SC-007**: 템플릿 규칙을 위반한 개설 요청이 100% 400으로 차단되고, 규칙을 지킨 요청의 특화 데이터는 손실 없이 저장된다.
- **SC-008**: 명예의 전당에는 완주한 정규 스터디만, Post-mortem 목록에는 회고 등록 정규 스터디만 나온다. 두 목록에 `chat_url` 노출 0건.
- **SC-009**: 핵심 도메인 로직(완주 판정, 상태 머신 전이, 권한 제어) 테스트 커버리지 90% 이상. (NFR-006)

## Assumptions

- **리더 판정 처리**: 리더는 판정 대상이 아니며, 판정 확정 시 리더의 참여 상태는 자동 `COMPLETED`, 카운트는 `leader_count`만 +1 한다(`completed_count`는 올리지 않는다). trd.md §4.2의 "리더 본인 자동 가산"을 리더 횟수 가산으로 해석했다.
- **판정 창 종료일**: requirement.md는 진입을 "15일~말일"로만 적었으나, Grace Period가 익월 10일까지이므로 그때까지 판정을 허용한다. 익월 10일 이후 자동 이관은 Phase 4 Cron 범위다.
- **회고와 완주는 배타적**: 회고가 등록된 사이클은 실패로 확정된 것으로 보고 이후 완주 판정을 막는다. 반대로 완주한 글에는 회고를 받지 않는다.
- **회고 길이**: 원문에 제한이 없어 공백 제외 1~1000자로 정했다.
- **동시성**: 판정은 참여와 같은 방식으로 대상 글 행을 잠그고 처리한다. trd.md §4.2 예시 코드에는 잠금이 없으므로 plan 단계에서 trd를 함께 정정한다.
- **템플릿 특화 데이터 기본안** (전부 선택 입력이되, 지정 시 형식 검증):
  - 코딩테스트(`coding-test`): 플랫폼(백준·프로그래머스·리트코드·기타), 주간 목표 문제 수(1~50)
  - 모각코(`mogakco`): 주간 모임 횟수(1~7), 모임 시간대(텍스트 ≤20자)
  - 책 완독(`book`): 책 제목(필수, ≤60자), 총 페이지(1~5000)
  - 듀오링고(`duolingo`): 학습 언어(필수, ≤20자), 일일 목표 XP(1~1000)
  - 음악 감상(`music`): 장르(≤20자), 주간 감상 앨범 수(1~20)
  - 자유(`free`): 특화 데이터 없음
- 인증은 Phase 0 Mock 세션을 재사용하고, 테스트는 실제 Supabase에 붙어 트랜잭션 롤백으로 격리한다(TRUNCATE 금지).
- 필요한 컬럼(`template_id`, `template_data`, `proof_type`, `proof_url`, `postmortem_text`, `completed_count`, `leader_count`, 참여 상태 `COMPLETED`/`INCOMPLETE`)은 Phase 0 스키마에 이미 있어 마이그레이션이 필요 없을 것으로 본다.
