# [상세 PRD] 모두의 42 (Modu-42) — 해커톤 MVP 실행 명세서

* **문서 버전:** v1.0 (Production-Ready MVP)
* **타임라인:** 10.17 ~ 10.18 (해커톤 프로토타입 배포)


* **핵심 원칙:** 자체 채팅/복잡한 승인 플로우 배제, 외부 링크 라우팅과 가벼운 참여 기록(Log) 결합

## 1. 핵심 아키텍처 결정 사항 (Engineering Decisions)

해커톤 기간 내 병목을 없애기 위해 기획서의 모호한 지점을 다음의 규칙으로 확정합니다.

1. **참여 및 팀원 트래킹 (상세 모달 ➔ 최종 확인 팝업 ➔ 라우팅 및 기록):**
* 별도의 복잡한 '신청-리더 승인' 프로세스는 배제하되, 정보 확인 없는 무지성 참여 및 링크 노출을 방지합니다.
* **1단계 (상세 모달):** 유저가 대시보드 카드에서 `[상세보기 ↗]`를 클릭하면 상세 모달이 열려 스터디 소개, 목표, 규칙, 현재 참여자 목록을 확인합니다.
  - **공개 링크 (참고/이전 기록):** 리더가 등록한 이전 스터디 결과물(예: 이전 기수 깃허브 레포, 노션 회고 등 `reference_url`)이 있다면 비참여자에게도 **상시 공개 노출**하여 참여 판단을 돕습니다.
  - **비공개 링크 (소통 채널):** 실제 초대 링크(`chat_url`)는 비참여자에게 마스킹(비공개) 처리되지만, 리더가 선택한 **소통 플랫폼 종류(`chat_platform`: 카카오톡 오픈채팅 vs 디스코드)** 배지는 상세 모달에 상시 노출되어 사전 인지할 수 있게 합니다.
* **2단계 (확인 팝업):** 모달 내 `[참여하기]` 클릭 시 *"정말 참여하시겠습니까? 참여 후에는 취소가 불가능하며 오픈채팅방으로 이동합니다."* 확인 모달이 노출됩니다.
* **3단계 (기록 및 라우팅):** 유저가 최종 확정하는 순간 DB `participants` 테이블에 `(post_id, user_id)`가 `JOINED` 상태로 즉시 Insert되고 `current_members + 1`이 반영되며, 동시에 새 탭으로 오픈채팅 링크가 열립니다.
* **재열람 보장 (취소 불가 원칙):** 팝업을 통해 신중하게 확정한 참여이므로 **자진 취소는 불가**하며, 참여 완료 유저는 상세 모달에서 오픈채팅 링크를 언제든 상시 재열람(`[오픈채팅 바로가기 ↗]`)할 수 있습니다.

2. **정원 정책 및 리더 자동 포함 (강퇴 배제 사유):**
* **정원 기준:** 리더 본인을 포함하여 기본 10명 (개설 즉시 리더가 첫 멤버로 자동 등록되어 `1/10명`으로 시작).
* **강퇴 불필요:** 10명 안팎으로 여유 있게 모집하고, 1개월 사이클 종료 후 완주 판정 단계에서 리더가 체크박스로 미참여자를 선별하면 되므로 복잡한 강퇴/내보내기 기능은 배제.

3. **캠퍼스 장벽 없는 통합 플레이그라운드 (온라인 중심):**
* 지역/캠퍼스로 유저를 분리하거나 피드를 필터링하지 않습니다.
* "온라인 어디서든 함께 공부하자"는 프로젝트 핵심 목표에 따라 모든 42인이 경계 없는 단일 피드에서 어울리며, 오프라인 모임의 경우에만 상세 정보의 장소 텍스트로 위치를 확인합니다.

4. **정규 스터디 템플릿 프리셋:**
* 자유 주제를 허용하되, 폼 입력을 최소화하기 위해 `코테(born2solve)`, `모각코`, `책 완독`, `듀오링고`, `음악 감상`, `자유 주제` 6가지 프리셋 버튼을 제공하여 클릭 시 기본 태그와 설명 양식이 자동 채워지게 합니다.

5. **시간축(호흡)에 따른 3단계 모임 체계:**
* **정규 스터디 (1~3개월, 긴 호흡):** 월 단위 고정 사이클(15~말일 모집 ➔ 익월 1일 시작). 지속적인 커리큘럼 및 완주 후 🏆명예의 전당 박제 / 미완주 시 🪦Post-mortem 아카이브.
* **단기 파티 (1개월 미만, 중간 호흡):** 상시 개설 가능. D-Day(목표일) 타이머 기반의 유연한 모집 (해커톤 팀 빌딩, 컨퍼런스 동행, 단기 모의 코테 등). **마감일 도래 시 별도 판정 없이 모집 종료** — 조회에서 제외하고 참여를 막는 Lazy Filter 방식이며 상태값을 전이시키지 않습니다 (`requirement.md` FR-020).
* **지금 클러스터 / LIVE 핑 (30분~3시간, 초단기 휘발성):** 온라인 참여 버튼이나 채팅 링크가 없는 **'단순 위치 확인용(찾아가기)' 실시간 전광판**. 유효시간 경과 시 자동 소멸 (과제 디버깅 헬프, 아우터 과제 평가자 구인, 점심/저녁 밥친구, 배달 커피 쉐어 등). *추후 클러스터 외 지역 기반(Geo) 핑으로 확장 예정.*

### F1. GitHub 인증 및 세션 관리 (Auth & Session Gate) — `P0`

* **접근 제어 정책 (Protected Route & Auto-Redirect):** 
  - **비로그인 유저 (읽기 전용 열람, `FR-022`):** 대시보드(`/dashboard`) 조회는 허용한다. 루트(`/`) 접속 시에만 소개 랜딩 페이지(`/login`)를 표출한다. 대시보드에서는 피드·아카이브·랭킹·상세 모달을 읽을 수 있고, 쓰기 버튼(`[참여하기]`·`[스터디 개설하기]`·`[핑 보내기]`·리더 액션)은 `/login` 유도로 바뀐다. 상세 조회의 `chat_url`은 마스킹한다.
  - **로그인 유저 (Zero-Click 자동 직행):** 이미 유효한 세션이 있는 유저가 사이트 접속 시 랜딩을 건너뛰고 대시보드(`/dashboard`)로 0초 만에 자동 직행.
  - **로그아웃:** 사이드바 하단 프로필 영역에서 `[로그아웃]` 클릭 시 세션 쿠키 즉시 파기 후 소개 랜딩(`/login`)으로 이동.
* **인증 및 세션 기술 스펙:**
  - **인증 방식:** GitHub OAuth 2.0 (Authorization Code Grant). PKCE는 GitHub OAuth App이 지원하지 않으므로 쓰지 않고, `state` 파라미터 검증으로 CSRF를 막습니다.
  - **세션 쿠키:** Supabase Auth 세션 (`Max-Age=30일`, `HttpOnly`, `Secure`, `SameSite=Lax`). 30일간 재로그인 없이 지속 유지.
* **필수 수집 데이터:**
  - `github_id` (GitHub API `id` 필드 — 불변 숫자 식별자. 계정 매칭은 항상 이 값으로 합니다)
  - `login` (예: `borlee` — GitHub API `login` 필드. 화면에 표시하는 핸들이며 유저가 GitHub에서 변경할 수 있으므로 로그인마다 최신 값으로 갱신합니다)
  - *(참고: 외부 프로필 이미지 `avatar_url`은 일체 수집/저장하지 않으며, UI는 `login` 앞 2자리 이니셜 뱃지로 통일. 영문은 대문자로 올리고 숫자·하이픈은 그대로 씁니다)*
* **수집하지 않는 데이터:** `campus`(`GS`/`SEOUL`)는 GitHub 로그인으로 알 수 없으므로 `null`로 남습니다. 캠퍼스 뱃지는 42 Intra 추가 인증을 붙인 뒤에만 표출되며, 그 작업은 `requirement.md` §1.3 보류입니다.

### F2. 메인 대시보드 및 탐색 (Dashboard) — `P0`

* **레이아웃 구조:** 좌측 고정 네비게이션 바 + 우측 메인 피드.
* **섹션 구성:**
1. **마감 임박 단기 파티 (상단 가로 스크롤):** `type = 'PARTY'`이고 행사 시작일(`start_date`)이 임박한 순서대로 정렬 (`D-3`, `D-5` 등 타이머 배지 노출). 피드 제외는 행사 종료일(`end_date`) 기준이다 (`FR-020`).
2. **모집 중인 정규 스터디 (메인 그리드):** `type = 'STUDY'`인 항목 출력. 최신순/마감임박순 정렬.
3. **지금 클러스터 (LIVE 핑 전광판):** 30분~3시간 초단기 휘발성 핑 가로 바 노출.
   - 대표 사례: *"philosopher 디버깅 30분만 도와주실 분"*, *"아우터 과제 평가자 구합니다"*, *"점심 밥친구 구해요"*, *"카페 배달비 쉐어하실 분"*
   - 설정된 유효시간 경과 시 목록에서 자동 소멸(TTL).
   - **작성자 조기 종료:** 동료를 일찍 만난 경우 작성자 본인에게 `[완료]` 버튼을 제공하여 전광판에서 즉시 조기 소멸 가능.
* **카드 UI 표출 데이터:**
* 공통: 제목, 리더 `login` & 이니셜 뱃지(예: `BR`), 현재 참여 인원 / 최대 인원 (`1/10명`). 리더가 42 추가 인증을 마친 경우에만 캠퍼스 뱃지(`42경산`/`42서울`)를 덧붙입니다(§1.3 보류).
* 정규 스터디 전용: 운영 사이클 (예: `11월 정규 · 4주`), 카테고리 태그.
* 단기 파티 전용: 태그 배지(예: `[해커톤]`), D-Day 카운트다운 배지(예: `D-3`, 행사 시작일 기준), 행사 기간 및 장소 표기 (예: `10/14 · 코엑스`(당일치기), `10/20~10/27 · 온라인`), 인원 (`1/2명`).
* LIVE 핑 전용: 내용, 위치(예: "오아시스 2열"), 남은 시간 카운트다운(예: "42분 남음"), 작성자 본인 전용 `[완료]` 버튼.

### F3. 스터디 / 파티 / LIVE 핑 생성 (Post Creation) — `P0`

유형(`type`) 선택에 따라 최적화된 입력 폼을 제공합니다.

* **LIVE 핑 초간편 폼 (Live Ping):**
  - **무엇을 함께/도와달라?**: 한 줄 텍스트 입력 (최대 50자, 예: *"philosopher 디버깅 30분만 도와주실 분"*, *"점심 밥친구 구해요"*)
  - **지금 어디에 있나요?**: 위치 텍스트 (예: *"오아시스"*, *"클러스터 2층"*, *"클러스터 3층"*)
  - **얼마나? (유효시간)**: 버튼 선택 (`30분` / `1시간` / `2시간` / `3시간`)
  - **생성 제한 (Spam 방지):** 유저당 **1일 1회(KST 자정 00:00 기준 당일 1개)** 로 엄격 제한. 이미 유효한 핑이 있거나 당일 작성 이력이 있으면 등록 비활성화 및 알림 안내.
  - **조기 종료 지원:** 작성자 본인은 전광판의 `[완료]` 버튼을 눌러 언제든 즉시 핑을 내릴 수 있음.
  - *원클릭 전광판 즉시 송출 및 설정 시간 만료 시 자동 소멸.*

* **정규 스터디 / 단기 파티 폼 (Study & Party):**

### F4. 상세 모달 조회 및 최종 참여 (View Detail & Join) — `P0`

* **User Action Flow:**
  1. **상세 조회:** 메인 카드에서 `[상세보기 ↗]` 클릭 ➔ 상세 모달 오픈.
     - **공개 열람:** 스터디 소개글, 목표, 규칙, 사이클, 현재 참여 멤버 목록, 모임 장소(`place`), **소통 플랫폼 배지(`카카오톡` or `디스코드`)**, **이전 활동/참고 링크(`reference_url`)**는 비참여자도 자유롭게 열람 가능.
     - **비공개 보호:** 실제 외부 초대 링크(`chat_url`)는 마스킹 처리되어 노출되지 않음.
  2. **참여 의사 표명:** 모달 하단 `[참여하기]` 클릭 ➔ 확인 팝업 모달 노출 (*"정말 참여하시겠습니까? 참여 후에는 취소가 불가능하며 오픈채팅방으로 이동합니다."*).
  3. **최종 확정:** 팝업에서 `[확인]` 클릭 ➔ 즉시 DB 참여 등록 및 오픈채팅 새 탭 라우팅.

* **System Logic:**
  1. 로그인 세션 검증 (비로그인 시 로그인 유도 모달).
  2. 이미 참여한 유저인 경우: 버튼이 `[오픈채팅 바로가기 ↗]`로 고정 표시되며 클릭 시 링크만 바로 오픈 (자진 취소 불가).
  3. 신규 참여 시:
     - `participants` 테이블에 `(post_id, user_id)` 레코드 Insert (`status = 'JOINED'`).
     - `posts.current_members` 1 증가.
     - `window.open(chat_url, '_blank')` 실행.
  4. 정원 도달 시: `current_members >= max_members` 도달 시 `status = 'CLOSED'` 전이되며, 미참여 유저에게는 `[모집 완료]` 비활성화 버튼 표시 (기존 참여자는 상시 링크 열람 가능).
  5. 리더 본인 조회 시 관리 액션 버튼:
     - **`[수정하기]`:** 오타 수정, 설명 보강, 오픈채팅 링크 변경, 장소(`place`) 수정을 지원하는 수정 모달 오픈.
     - **`[스터디 취소]`:** 시작 전 개설 취소 (`status = 'CANCELLED'`).
     - **`[종료 및 결과 기록]`:** 정규 스터디의 경우 15~30일 기간에 완주/실패 아카이빙 모달 오픈.

### F5. 스터디 종료 및 아카이빙 (Completion, Hall of Fame & Post-mortem) — `P0`

스터디 리더의 운영/출결 관리 부담을 덜고, 완주 결과물뿐만 아니라 실패한 스터디의 교훈도 자산으로 기록합니다. (🏆명예의 전당 및 🪦Post-mortem은 **정규 스터디 전용**이며, 단기 파티는 마감일 도래 시 판정 없이 모집만 종료됩니다 — `requirement.md` FR-020.)

* **진입 조건:**
  - **정규 스터디:** 월 단위 사이클 종료 시점인 **매월 15일~30일(말일)** 에 리더 본인이 작성한 게시글 상세 뷰에서 `[스터디 종료 및 결과 기록]` 버튼 활성화 (익월 스터디 모집 기간과 동시 진행).
  - **단기 파티:** 지정된 행사 종료일(`end_date`) 경과 시 별도 판정 없이 모집만 종료됩니다 (조회 제외·참여 차단, 상태 전이 없음. `requirement.md` FR-020). 정원 미달이나 행사 시작일 도래로는 종료되지 않습니다.
* **리더 액션 (단일 모달에서 2가지 경로 중 선택):**

  1. **경로 A: 완주 성공 (`[🏆 명예의 전당 등록]`)**
     - **팀원 완주 원클릭 판정 (필수):** 참여자 목록이 체크박스로 노출됨 (기본값 All Checked). 중도 이탈자만 체크 해제하여 원클릭으로 완주 판정 필수 수행.
     - **활동 증빙 URL 제출 (선택/자유):** 노션 회고록, 깃허브 레포, 구글 드라이브 등 결과물 링크 입력 (증빙 링크 없이도 완주 등록 가능).
     - **결과 반영:** 게시글 상태 `COMPLETED` 전이, 대시보드 하단 **`🏆명예의 전당`** 탭에 박제, **완주 처리 시 리더의 `leader_count` +1 가산**, 완주 판정된 팀원들의 `completed_count` +1 가산 및 **'성실 멤버 랭킹'**에 반영.

  2. **경로 B: 목표 미달성 / 실패 (`[🪦 Post-mortem 회고 등록]` 및 자동 분류)**
     - **리더 직접 작성:** 완주하지 못한 솔직한 이유(과제 일정 중복, 난이도 조절 실패 등)와 교훈을 텍스트로 기록.
     - **익월 10일 자동 미달성 처리 (Grace Period 만료):** 정규 스터디 사이클 종료 후 **익월 10일까지 팀원 완주 판정이 완료되지 않은 경우**, 시스템에서 자동으로 '목표 미달성'으로 분류하여 Post-mortem 목록으로 이관 (리더 횟수 및 팀원 완주 카운트 미가산).
     - **결과 반영:** 게시글 상태 `CLOSED` 유지, 대시보드 하단 **`🪦Post-mortem`** 탭에 박제되어 다음 동료들이 참고할 수 있는 실패 자산으로 보존 (이후에도 리더가 뒤늦게 회고록 작성 가능).

### F6. 유저 프로필 및 스터디 이력 (My Profile) — `P1`

디자인 원본: `docs/designs/myprofile.html` (`FR-019`).

* **진입:** 사이드바 하단 프로필 영역 클릭.
* **헤더:** `login`, `login` 앞 2자리 이니셜 뱃지. 외부 프로필 이미지는 쓰지 않습니다. 캠퍼스 뱃지(`42경산`/`42서울`)는 `campus`가 `null`이 아닐 때만 렌더하며, 디자인 원본의 기수(`2기`) 표기는 담을 컬럼이 없어 생략합니다.
* **누적 기록:** 완주 횟수(`users.completed_count`), 리더 횟수(`users.leader_count`). FR-008 완주 판정이 가산한 값을 그대로 읽습니다.
* **스터디 이력:** 참여한 글을 완주 / 리더 / 진행 중으로 구분해 나열. `participants` 레코드 기준이며 신규 테이블을 만들지 않습니다.
* **범위 밖 (보류):** 디자인 원본의 **개구리 도감**과 **획득 배지** 섹션은 포팅하지 않습니다. 수여 규칙·저장 스키마가 미정이라 `requirement.md` §1.3에 보류로 분류됐습니다.

## 4. 엣지 케이스 및 예외 방어 로직 (Edge Cases)

심사위원이나 테스트 유저가 시연 중 겪을 수 있는 문제에 대한 최소한의 방어선입니다.

1. **잘못된 오픈채팅 링크 입력 방어:**
   * 생성 폼에서 `https://open.kakao.com/...` 또는 `https://discord.gg/...` 등 유효한 URL 포맷인지 정규식으로 프론트엔드 1차 검증을 수행합니다.

2. **Cold Start 방지 & 심사위원 시연용 데모 데이터 주입:**
   * 배포 직후 빈 화면을 방지하고 해커톤 발표/심사 시 즉시 시연할 수 있도록 realistic한 시드 데이터(Seed Script)를 사전 주입합니다.
   * **시연용 데이터 구성:**
     - **모집 중 정규 스터디:** `born2solve 알고리즘 정복`, `매일 1커밋 모각코`, `듀오링고 프랑스어 완주` 등.
     - **마감 임박 단기 파티:** `파이콘 APAC 2026 동행 파티(D-2)`, `오픈소스 해커톤 팀원 모집(D-4)`.
     - **지금 클러스터 (LIVE 핑):** `philosopher 데드락 30분 헬프 구합니다 (클러스터 2층)`.
     - **아카이브:** 🏆명예의 전당 완주 표본 2건(깃허브/노션 링크 포함), 🪦Post-mortem 실패 회고 1건.
