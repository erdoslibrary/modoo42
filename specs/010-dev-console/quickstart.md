# Quickstart: 개발자 콘솔 검증 (010)

구현 완료 후 **사람이 직접** 확인하는 절차다. 자동 테스트가 덮는 범위는 `contracts/dev-console-api.md` C7에 있고 여기서 반복하지 않는다.

## 0. 선행 준비

```bash
# .env.local에 콘솔 비밀번호를 넣는다. 이 키가 없으면 콘솔은 아예 열리지 않는다.
echo 'DEV_CONSOLE_PASSWORD=<아무-문자열>' >> .env.local

pnpm sandbox:sync      # dev_sandbox 스키마 재생 (최초 1회 + 스키마 변경마다)
pnpm dev
```

`pnpm sandbox:sync`는 `dev_sandbox`를 **DROP하고 다시 만든다.** `public`은 건드리지 않는다. 실행 전에 출력되는 대상 스키마 이름이 `dev_sandbox`인지 확인한다.

필수 게이트 5종은 별도로 돌린다.

```bash
pnpm lint && pnpm typecheck && pnpm test && pnpm build && pnpm drizzle-kit check
```

## 1. 게이트 (US2 · `TC-DEV-03`)

1. `.env.local`에서 `DEV_CONSOLE_PASSWORD`를 **주석 처리**하고 `pnpm dev`를 다시 띄운다.
2. `/login`에 콘솔 입구가 **없다.**
3. `curl -i -X POST localhost:3000/api/dev/console -d '{"password":"x"}'` → **404**.
4. `curl -i -X POST localhost:3000/api/mock-auth -d '{"persona":"gs_leader"}'` → **404**.
5. 브라우저 개발자 도구에서 `modoo42_dev_clock=86400000`을 심고 대시보드를 새로고침 → **시각이 변하지 않는다.**
6. 키를 되살리고 다시 띄운다.

## 2. 진입과 스냅샷 (US4 · `TC-DEV-05`)

1. `/login` → 콘솔 입구 → 비밀번호 입력. **이미 로그인한 상태면 `/login`이 `/dashboard`로
   되돌리므로**, 화면 우하단 `Dev Console` 패널을 펼쳐 그 안의 진입 칸에 비밀번호를 넣는다.
2. 안내 카피를 확인한다 — "이 세션에서 만든 데이터는 `dev_sandbox`에 들어가고 다음 진입 시 사라집니다."
3. 대시보드를 열어 **운영과 같은 글 목록**이 보이는지 확인한다(스냅샷).
4. 아무 글의 상세 모달을 열어 **플랫폼 배지가 그대로 보이고**, `[참여하기]` 확인 팝업에 오픈채팅방 문구가 남아 있는지 확인한다. 열리는 링크는 `dev-sandbox` 더미이고 실제 방이 아니다 (`contracts/sandbox-isolation.md` S4).
5. 글을 하나 만들고 참여까지 한다.
6. 쿠키 `modoo42_dev_console`을 삭제하고 새로고침 → **운영 피드에 그 글이 없다** (`TC-DEV-09`).

## 3. 시각 이동 (US1 · US5)

1. 콘솔에 다시 들어간다(합류 또는 재초기화).
2. 패널 시계 섹션의 유효 시각이 1초마다 흐르는지 본다.
3. 정규 스터디를 하나 만든다. `end_date`가 자동 산출된다.
4. 시나리오 `판정창 열림`을 누른다 → 그 스터디의 리더 화면에 완주 판정 입구가 열린다 (`FR-008`).
5. 판정을 수행한다. 랭킹·명예의 전당에 반영되는지 본다.
6. 시나리오 `Grace 만료`를 누른다 → 미판정 스터디가 기한 경과로 보인다 (`FR-018` 검증 준비).
7. `[실제 시각으로 복귀]`를 누른다 → 유효 시각이 실제 시각으로 돌아온다.
8. 과거로 이동한 뒤 글을 만들고, 그 글의 `created_at`이 과거인지 확인한다 (`TC-DEV-12`). 아카이브에 과거 사이클로 들어가야 한다.

## 4. LIVE 핑 경계 (US1 · US5)

1. LIVE 핑을 등록한다(유효시간 30분).
2. 상세 모달의 "이 글 기준으로 이동" → `LIVE 만료 직전` → 전광판 카운트다운이 1분 미만으로 보인다.
3. `LIVE 만료 직후` → 전광판에서 사라진다. 상태값은 `RECRUITING`으로 남는다 (Lazy Filter).
4. 같은 유저로 LIVE 핑을 또 등록 → **400**(1일 1회).
5. `다음 KST 자정` → 다시 등록된다 (`FR-011`).

## 5. 세션 우선순위 (US3)

1. GitHub OAuth로 로그인한다.
2. 패널 인증 섹션의 해석 소스가 `session`이다. 페르소나 버튼을 눌러도 유저가 바뀌지 않는다.
3. 세션 쿠키 삭제 버튼을 누른다 → 해석 소스가 `비로그인`이 된다.
4. 페르소나 `gs_member`를 고른다 → 해석 소스가 `persona`가 되고 화면의 유저가 바뀐다.

## 6. 2창 실시간 (US6 · `TC-DEV-07` · `NFR-004`)

1. 일반 창에서 콘솔 진입 후 모집 글을 만든다.
2. **시크릿 창**으로 같은 비밀번호로 진입한다 → 1번 창의 글이 **그대로 남아 있다**(표식 합류).
3. 시크릿 창에서 그 글에 참여한다 → 1번 창의 인원 수가 **1초 이내** 갱신된다.
4. 두 창 모두 닫고 2시간 뒤(또는 표식 행을 직접 만료시킨 뒤) 다시 진입 → 초기화가 수행돼 글이 사라진다.

## 7. 미래 점프와 세션 (US2 · `TC-DEV-04`)

1. 시계를 **+40일**로 옮긴다.
2. 콘솔에서 쫓겨나지 않고 로그인 상태도 유지된다 — 세션 만료는 실제 시각을 본다.
3. `[실제 시각으로 복귀]`로 돌아온다.

## 8. 되돌리기의 한계 확인 (문서화된 동작)

1. 완주 판정을 한 뒤 시계를 사이클 중으로 되돌린다.
2. "사이클 중인데 이미 `COMPLETED`"인 글이 보인다. **이것은 버그가 아니다** — 패널 하단 문구가 설명한다. 상태 롤백은 범위 밖이다 (`spec.md` FR-025).
