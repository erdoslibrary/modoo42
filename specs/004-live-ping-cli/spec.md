## User Scenarios & Testing *(mandatory)*

### User Story 1 - LIVE 핑 등록 (Priority: P1)

클러스터에 있는 카뎃이 "philosopher 데드락 30분 헬프 구합니다"처럼 한 줄 내용, 현재 위치("클러스터 2층"), 유효시간(30분/1시간/2시간/3시간)만 골라 LIVE 핑을 올린다. 핑은 즉시 "지금 클러스터" 전광판에 뜨고, 유효시간이 지나면 저절로 사라진다. 도배를 막기 위해 한 사람은 KST 하루(00:00 기준)에 한 번만 올릴 수 있다.

**Why this priority**: FR-011의 본체. 조기 완료(US2)와 CLI 조회(US3)는 등록된 핑이 있어야 의미가 있다.

**Independent Test**: 로그인 유저가 LIVE 핑을 1건 생성 → 활성 목록에 노출, 같은 날 두 번째 생성 → 400. 만료 시각을 과거로 둔 핑은 목록에서 빠지는지 확인.

**Acceptance Scenarios**:

1. **Given** 오늘 LIVE 핑을 올린 적 없는 로그인 유저, **When** 내용 50자 이하·위치·유효시간 1시간으로 등록, **Then** `RECRUITING` 상태 핑이 생성되고 만료 시각은 생성 시각 + 1시간, 정원·채팅 링크는 비어 있다. (TC-LIVE-01)
2. **Given** 등록 요청, **When** 내용이 51자 이상이거나 비어 있음, 또는 유효시간이 4종 외(예: 45분), **Then** 400, 핑은 생성되지 않는다. (TC-LIVE-01)
3. **Given** 같은 KST 날짜에 이미 핑 1건을 올린 유저(그 핑이 활성·조기 완료·만료 중 무엇이든), **When** 두 번째 등록, **Then** 400. (TC-LIVE-02)
4. **Given** 전날 23:59 KST에 핑을 올린 유저, **When** 다음날 00:00 KST 이후 등록, **Then** 정상 생성된다(하루 경계는 KST 자정).
5. **Given** 오늘 핑이 없는 유저가 등록 요청 2건을 동시에 보냄, **When** 처리, **Then** 정확히 1건만 생성되고 나머지는 400. (TC-LIVE-02)
6. **Given** 만료 시각이 지난 `RECRUITING` 핑, **When** 누구든 활성 목록 조회, **Then** 그 핑은 목록에 없고 상태는 여전히 `RECRUITING`이다. (TC-LIVE-04)
7. **Given** 비로그인 요청, **When** 등록, **Then** 403.

### User Story 2 - LIVE 핑 조기 완료 (Priority: P2)

핑을 올린 사람이 동료를 일찍 만나면 전광판의 `[완료]`를 눌러 핑을 즉시 내린다. 핑은 `CLOSED`가 되어 활성 목록에서 바로 빠진다.

**Why this priority**: 이미 해결된 요청이 유효시간 내내 떠 있으면 전광판 신뢰도가 떨어진다. 등록(US1) 다음으로 필요하다.

**Independent Test**: 작성자가 활성 핑을 완료 → `CLOSED` 전이 및 활성 목록에서 제외. 다른 유저가 완료 시도 → 403.

**Acceptance Scenarios**:

1. **Given** 작성자의 활성 핑, **When** 작성자가 완료, **Then** `status = 'CLOSED'`가 되고 활성 목록에서 즉시 사라진다. (TC-LIVE-03)
2. **Given** 남의 핑, **When** 작성자가 아닌 유저가 완료 시도, **Then** 403. (TC-LIVE-03)
3. **Given** 이미 `CLOSED`인 핑, **When** 작성자가 다시 완료, **Then** 상태 변화 없이 성공 응답(멱등).
4. **Given** 만료 시각이 지났지만 `RECRUITING`인 핑, **When** 작성자가 완료, **Then** `CLOSED`로 전이된다(목록 노출에는 영향 없음).
5. **Given** 정규 스터디·단기 파티 글, **When** LIVE 핑 완료 동작 호출, **Then** 400.
6. **Given** 없는 글 ID, **When** 완료 호출, **Then** 404.

### User Story 3 - 터미널 CLI 조회 (Priority: P3)

카뎃이 클러스터 터미널에서 `curl <서비스 주소>/api/list`만 쳐서 지금 모집 중인 정규 스터디·단기 파티와 활성 LIVE 핑을 한눈에 본다. 기본 응답은 색이 입혀진(ANSI) 읽기 좋은 텍스트이고, 스크립트용으로 JSON을 요청할 수도 있다. 로그인 없이 동작한다.

**Why this priority**: 42 정서에 맞는 부가 접점이지만 웹 대시보드(Phase 3)와 핵심 도메인 없이는 가치가 없다.

**Independent Test**: 쿠키 없이 `GET /api/list` → 200, 텍스트 본문에 모집 중 글·활성 핑이 보이고 어떤 채팅 링크도 없다. JSON 요청 시 같은 내용이 구조화되어 온다.

**Acceptance Scenarios**:

1. **Given** 모집 중 스터디·파티와 활성 핑, 마감·완료·취소된 글과 만료된 핑이 섞여 있음, **When** 비로그인 `GET /api/list`, **Then** 200, 모집 중(`RECRUITING`) 스터디·파티와 활성 핑만 유형별로 묶여 텍스트로 나온다. (TC-CLI-01)
2. **Given** 같은 데이터, **When** JSON 형식을 요청, **Then** 같은 항목이 JSON으로 나온다. (TC-CLI-01)
3. **Given** 어떤 형식이든, **When** 응답 확인, **Then** 채팅 링크(`chat_url`)는 한 건도 포함되지 않는다. (TC-CLI-01)
4. **Given** 노출할 항목이 0건, **When** 조회, **Then** 200과 "모집 중인 글이 없다"는 안내가 나온다.
5. **Given** 텍스트 응답, **When** 색을 해석하지 못하는 환경에서 색 제거를 요청, **Then** 제어 문자 없는 평문이 나온다.

---

### Edge Cases

- LIVE 핑은 참여 기능이 없다. LIVE 핑에 참여 시도 → 400.
- LIVE 핑에는 리더용 마감/재모집 토글·정보 수정·중도 취소·완주 판정·Post-mortem이 적용되지 않는다. 시도 → 400. 특히 `CLOSED` 핑을 `RECRUITING`으로 되돌릴 수 없다.
- 하루 1회 계산은 핑의 현재 상태와 무관하게 "그 KST 날짜에 생성한 LIVE 핑 수"로 한다. 정규 스터디·단기 파티 생성은 세지 않는다.
- 유효시간이 KST 자정을 넘어가도(예: 23:30 등록, 2시간) 그 핑은 등록일 몫으로만 센다.
- 일반 게시글 목록 조회에도 Lazy Filter가 적용된다. 만료되었거나 `CLOSED`인 LIVE 핑은 어떤 목록에도 노출되지 않는다.
- 상세 조회는 만료·완료된 핑도 ID로 열람할 수 있다(목록에서만 제외).
- 위치를 비워 보내면 400. LIVE 핑은 "찾아가기" 용도라 위치가 필수다.
- CLI 텍스트에서 사용자 입력(제목·위치)에 섞인 터미널 제어 문자는 제거한 뒤 출력한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 로그인 유저가 내용(1~50자)·위치(필수)·유효시간(30분/1시간/2시간/3시간 중 하나)으로 LIVE 핑을 생성할 수 있게 해야 한다. (req FR-011)
- **FR-002**: LIVE 핑의 만료 시각은 생성 시각 + 유효시간으로 고정되며, 정원과 채팅 링크는 갖지 않는다.
- **FR-003**: 시스템은 유저당 같은 KST 날짜(00:00~23:59:59)에 LIVE 핑을 1건만 생성하도록 제한하고, 초과 시 400을 반환해야 한다. 동시 요청에서도 이 제한이 지켜져야 한다. (req FR-011, CLAUDE.md §7.2)
- **FR-004**: 시스템은 활성 LIVE 핑을 `RECRUITING` 상태이면서 만료 시각이 현재보다 뒤인 것으로 정의하고, 모든 목록 조회에서 활성 핑만 노출해야 한다. 만료는 상태 전이를 일으키지 않으며 별도 정기 작업을 두지 않는다. (CLAUDE.md §6.4)
- **FR-005**: 작성자 본인은 자기 LIVE 핑을 조기 완료해 `CLOSED`로 전이할 수 있어야 한다. 작성자가 아니면 403, LIVE 핑이 아니면 400, 이미 `CLOSED`면 변화 없이 성공한다. (req FR-011, trd `POST /api/posts/:id/complete-ping`)
- **FR-006**: LIVE 핑에 대한 참여·마감/재모집 토글·수정·중도 취소·완주 판정·Post-mortem 요청은 400으로 거부해야 한다.
- **FR-007**: 시스템은 인증 없이 호출 가능한 CLI 조회(`GET /api/list`)를 제공해야 한다. 노출 대상은 `RECRUITING` 정규 스터디·단기 파티와 활성 LIVE 핑이다. (req FR-012)
- **FR-008**: CLI 조회의 기본 응답은 ANSI 색 텍스트이며, 요청에 따라 JSON 또는 색 없는 평문을 반환해야 한다.
- **FR-009**: CLI 조회 응답은 어떤 경우에도 채팅 링크를 포함하지 않아야 한다. 항목별 노출 필드는 유형, 제목(LIVE는 내용), 태그, 현재/최대 인원, 마감일(파티) 또는 남은 시간(LIVE), 작성자 intra ID, 장소(LIVE는 위치)다.
- **FR-010**: CLI 텍스트 출력은 사용자 입력의 터미널 제어 문자를 제거해야 한다.

### Key Entities

- **LIVE 핑**: 게시글의 한 유형. 작성자, 내용(≤50자), 위치, 생성 시각, 만료 시각, 상태(`RECRUITING`/`CLOSED`)를 가진다. 정원·채팅 링크·참여자·완주 기록이 없다. 상태가 `CLOSED`가 되면 다시 열 수 없다.
- **일일 생성 이력**: 별도 엔티티가 아니라 "작성자 + KST 생성일" 기준의 LIVE 핑 개수로 판단한다.
- **CLI 목록 항목**: 웹 목록의 공개 요약본. 채팅 링크가 없는 읽기 전용 투영이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 유저는 3개 입력(내용·위치·유효시간)만으로 LIVE 핑을 올릴 수 있고, 등록 직후 다음 목록 조회에 핑이 나타난다.
- **SC-002**: 같은 유저가 같은 KST 날짜에 두 번째 핑을 올리려는 시도는 동시 요청 10건을 포함해 100% 거부된다.
- **SC-003**: 만료 시각이 지난 핑과 조기 완료된 핑은 다음 목록 조회부터 0건 노출된다.
- **SC-004**: 로그인 없이 터미널 명령 한 줄로 모집 현황을 받을 수 있고, 응답에 채팅 링크가 0건 포함된다.
- **SC-005**: 인수 테스트 TC-LIVE-01~04, TC-CLI-01이 모두 통과하고, 핵심 도메인 로직(일일 제한·조기 완료 권한·상태 차단) 커버리지 90% 이상이다.

## Assumptions

- 일일 제한은 `docs/requirement.md` FR-011의 "KST 자정 기준"을 따른다. PRD의 "최근 24시간" 표현은 같은 PR에서 KST 자정 기준으로 정정했다.
- LIVE 핑 등록은 기존 게시글 생성 경로를 유형만 바꿔 재사용한다(trd §4 `POST /api/posts`). 태그·템플릿은 LIVE 핑에 쓰지 않는다.
- LIVE 핑은 오프라인 "찾아가기" 용도이므로 온/오프라인 구분은 오프라인으로 고정한다.
- 조기 완료 재호출은 400 대신 멱등 성공으로 처리한다. 사용자가 버튼을 두 번 눌러도 오류를 보지 않게 하기 위함이다.
- CLI 공개 필드에 작성자 intra ID와 LIVE 위치를 포함한다(2026-10-18 사용자 결정). 외부인도 카뎃의 실시간 위치를 볼 수 있다는 점을 감수하고 "터미널에서 바로 찾아가기" 가치를 택했다.
- CLI 형식 선택은 쿼리 파라미터로 한다. 기본값은 ANSI 텍스트다.
- Rate Limit(NFR-005)은 Phase 4 범위이며, 이 Phase의 일일 1회 제한과 별개다.

**범위 밖(이 Phase 비대상):** 전광판 UI·카운트다운 렌더링과 Realtime prepend는 Phase 3(FR-013, FR-014). Rate Limit(NFR-005)은 Phase 4. 지역 기반(Geo) 핑 확장은 미정.
